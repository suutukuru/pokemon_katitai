# ADR-0012: 知り得ない情報を使わずに決め、結果から振り返って改善する

- 状態: 採用
- 日付: 2026-11-24

## 背景

ADR-0011 の探索は局面の**完全な状態**から先読みしていた。つまり相手の未公開の技・持ち物・特性・努力値（素早さ）・
まだ出ていない後ろの2体を「知っている」前提で手を選んでいた。実戦では知り得ない情報であり、評価も選択も楽観的に歪む。
また、決めたときの予想と結果を比べる仕組みがなく、改善の手がかりが残らなかった。

## 決定

### 1. 知り得る情報だけで決める（belief.ts / search.ts の planner モード）

- **観測**（`observe`）: その側から見える公開ログだけを読む。相手のチームプレビュー6体、場に出たポケモン、使った技（move slot の `used`）、
  表示された持ち物・特性（`-item` / `-enditem` / `[from] item:` / `-ability` / `[from] ability:` / `-mega`）、HP%、場の状態。
  さらに**行動順から素早さの大小**を読む（同じ優先度の攻撃技、天候・フィールド・トリックルーム・おいかぜが無いターン、素早さ変化・まひ・メガが無いポケモンに限る）。
- **ありうる世界**（`determinize`）: 実際の状態のうち、相手の非公開部分だけを使用率（Smogon, ADR-0010）から抽選して差し替える。
  技は公開済み＋使用率で抽選、持ち物はアイテム被りなし（場に出てメガシンカしなかったポケモンにメガストーンは持たせない）、
  性格・SP は観測した行動順と矛盾しない配分から抽選、未登場の後ろはプレビューの未登場種から抽選。HP は%を保つ。
  公開情報（HP%、状態、場、使用済みの技）は変えない。メガシンカ済みのポケモンは実数値を差し替えない（既知の制限）。
- **相手の選択肢は「意図」で表す**（policy.ts の intent）: 未公開の技名は使えないため、「一番強い攻撃→枠t」「まもる系」「全体攻撃」「補助技」「交代」
  「（公開済みなら）その技」で列を作り、各世界でその世界の技に解決する。
- 探索は、自分の具体的な行動（行）× 相手の意図（列）の表を、世界をまたいだロールアウトで埋めて解く。
  世界の数は `searchWorlds`、相手の列は不確かなので `searchOpponentExtra` 列多く残す。
- 最善手同士の対戦（bestplay）・選出の強い評価・Web の対戦盤は、各側が**自分から見える情報だけ**で探索する。
  相手の実際の行動は、選んだ意図を実際の対戦で解決したもの（Web の「相手視点で探索」は相手側も同じ制約で探索）。
- テスト: 公開情報が同じで相手の非公開の型だけが違う2つの対戦で、planner の分析結果が**完全に一致**すること（完全情報の探索では変わること）を確認。

### 2. 振り返り（reflection.ts）

判断ごとに `DecisionReview`: 決めたときの予想勝率、相手の実際の行動（列）とそれに付けていた確率、
その行動に対する自分の手の勝率と、後から見た最善手の勝率（差 = 損失 regret）、最終結果。
集計（`summarizeReviews`）は Brier スコア、予測勝率と実際の勝率（区間ごと）、相手の行動を候補に入れていた割合、後から見ても最善だった割合、平均損失。

### 3. 改善

- `pnpm sim:review` が多数の対戦で振り返りを集計し、損の大きかった判断を挙げる。`--fit` で、予測勝率→実際の勝率の補正
  `σ(a·logit(p)+b)` を推定して `weights.json` の `evalCalibA/B` に書く（30戦以上のときだけ）。表示する勝率に使う（手の順位は変わらない）。
- `pnpm sim:tune` が行動方針の重みを1つずつ ±`step` 変えて、**同じ乱数・左右入れ替えの対局**で現行と戦わせ、
  現行より `z` 標準誤差以上強いときだけ採用する（`--write` で weights.json に反映）。
- **検証**: 1項目ずつの試行を何十回も 2標準誤差で判定すると偶然の「勝ち」が混ざる。実際、最初の調整で採用した2項目
  （koFirstBonus 0.25→0.325: 52.0%±1.8、redirectionValue 0.3→0.21: 51.5%±1.1、各600戦）は、別のチーム・乱数での2000戦で
  49.3%±1.2 と改善が再現しなかった。そこで調整の最後に、通過した変更をまとめて**使っていない乱数**で元の重みと対戦させ、
  なお基準を満たすときだけ書き込むようにした（`validate`、既定は試行1回の2倍の対戦数）。
- 最初の振り返り（team2 × 上位4構築 × 2戦）で「相手の実際の行動を候補に入れていた割合 55%」と分かったため、相手の列を増やし、
  意図の候補をすべての世界から集めるよう変更した（`searchOpponentExtra`）。

## 影響・今後

- 1判断あたりの計算は世界を作る分（数十ms）と、両者が別々に探索する分（最善手同士の対戦では約2倍）増える。
- 振り返りの統計は、同じ対戦の判断どうしが相関するため、実質の標本数は対戦数。補正の書き込みに最低対戦数を設けた。
- 未対応: メガシンカ後の実数値の抽選、交代読みなど行動の履歴からの推論、相手の選出の推論（チームプレビューからの選出確率）。
