# ADR-0011: 毎ターンの読み合いを探索で解き、同じエンジンをブラウザでも動かす

- 状態: 採用
- 日付: 2026-11-22

## 背景

ADR-0009 のシミュレーションは「両者が同じ確率的ヒューリスティックで動く」前提で、選出・立ち回りの評価が方針の弱さに引きずられていた。
また、試すには CLI が必要で、iPhone からは事前に作った画像やHTMLを見るだけだった。

## 決定

### エンジン（packages/sim）

1. **行動方針の改良（policy.ts）**: 2体の行動を組（joint）で評価する。同じ相手へのダメージは合算してから価値に換算（2体で倒せるなら倒した価値、片方で足りるなら過剰分は数えない）。
   素早さ順（トリックルーム込みの `getActionSpeed`）を見て、先に倒される側の攻撃は割り引き（`koFirstDiscount`）、先に倒せるなら加点（`koFirstBonus`）、先に倒されそうならまもるを加点。
   瀕死後の交代先は控えの相性（与える／受ける最大ダメージ）で選ぶ。旧方針との対戦で 53.9%（800戦、±1.8%）。
2. **同時手番の探索（search.ts）**: 局面ごとに
   (a) 両者の候補（方針の上位 `searchWidth` ＋ 各枠の全選択肢の最良の組み合わせ）、
   (b) 相手は方針のままでの少数ロールアウトで各 `searchKeep` 個に絞り込み、
   (c) 残りの総当たり表を各 `searchMatrixRollouts` 戦（**同じ k 番目の対戦は同じ乱数シード**＝共通乱数で、候補間の比較の分散を下げる）、
   (d) ゼロサムゲームとして架空プレイで均衡を解き、均衡で使う行・列に `searchRefineRollouts` 戦を追加して解き直す。
   出力は各候補の「相手が均衡の混ぜ方で来たときの勝率」「最悪の返しに対する勝率」「均衡での採用割合」と局面の評価値（均衡値）。
   瀕死後の交代も同じ仕組みで解く。探索あり vs 方針のみで 62.5%（48戦、半分の予算）。
3. **最善手同士の対戦（bestplay.ts）**: 毎回の判断で両者が均衡の最有力手を選ぶ。各ターンの評価値・候補一覧を記録。
4. **選出の強い評価（analyze.ts の strong 段階）**: 予備戦→総当たり表で上位に来た選出 `strongConfigs`×`strongConfigs` を、最善手同士の対戦（小さめの予算 `strongSearchScale`）で評価し直し、
   総当たり表の値を事前分布（2戦分）として混ぜた表から推奨選出を決める。
5. **実行器の抽象化**: ロールアウトは `RolloutExecutor`（状態1つ＋手の組のリスト→勝敗）。同じ入力を固定順で分割するので、1スレッド／ワーカースレッド（Node）／Web Worker（ブラウザ）で結果が同じ。
6. **局面キー（positionKey）**: 対戦ログ全体のハッシュ。同じチーム・同じ手順なら同じキーになり、事前計算した評価を再利用できる。

### ブラウザ（apps/web）

- `pokemon-showdown` をライブラリとして書き換えずに、esbuild で**ブラウザ用にバンドル**する（`apps/web/scripts/build-showdown.mjs`）。
  データの動的 `require` と `fs.readdirSync` を固定の表に差し替え、Champions に必要なデータ（基本データ＋champions mod）だけを入れる（約1.9MB, gzip 約420KB）。
  学習技・説明文は対戦に不要なので入れない。Node 版と同じ対戦ログになることをテストで確認（`apps/web/test/showdown-bundle.test.ts`）。
- 画面: パーティ（メンバーと実数値、コピーして改造・新規作成）／選出分析（端末内で並列シミュレーション、または事前計算の結果）／対戦盤（1手ずつ自分で選び、相手は均衡の混ぜ方・最有力・指定から選ぶ。各局面を自動で探索して評価値を出す）／診断。
- `pnpm web:data` が CLI（全コア）で重い計算をしてから `apps/web/src/data/` に保存する。対戦盤は同じ手順をたどる限り事前計算の評価を即表示し、外れたら端末で探索する。

## 影響・今後

- 探索の深さは1手（その先は方針どおりのロールアウト）。将来は2手目以降の探索、方針の重みの自動調整（探索結果を教師にする）。
- 評価値は「この方針の続き方なら」の推定。表示では「推測を含む」と明記する。
- Showdown のバージョンを上げたら `build-showdown.mjs` の表と同値テストを確認する。
