# ADR-0007: ルールエンジンの構成（宣言的ルール + データ駆動の重み・閾値）

- 状態: 採用
- 日付: 2026-11-21

## 決定

- ルールは `Rule { id, version, category, params, appliesTo, evaluate }`。`evaluate` は 0〜1 のスコアと Finding の下書き（根拠1件以上が型で必須）を返す。
- 重み（`weights.rules`）、閾値（`weights.params`）、スコア→重要度の境界（`weights.severity`）はすべてレギュレーションの `weights.json`。コードに数値を書かない。足りない値は実行前に検出して止める。
- チームのスコア = Σ(重み × ルールのスコア) / Σ重み（適用されたルールのみ）。将来の重み学習（フェーズ6）はこの重みを置き換える。
- 技・特性の分類（すばやさ操作、ねこだまし、天気を起こす特性、タイプ無効、-ate 特性など）は `packages/data/engine/tags.json` に置き、zod で検証、ID の実在をテストで確認。
- Finding の並び順は 重要度 → ルール順 → explainKey → パラメータ（正規化JSON）で決定的。結果に `AnalysisMeta`（レギュレーション、contentHash、エンジン版、使用率スナップショット）を付ける。
- 改善案は計算で検証できるものだけ出す（現状はすばやさのSP調整: `calcStat` で新しい実数値を出して確認）。覚える技のデータ（learnset）が無いため、技の変更案はまだ出さない。
- 使用率データに依存するルールは、スナップショットが渡されたときだけ適用（`appliesTo`）。データが無いのに推測で埋めない。
