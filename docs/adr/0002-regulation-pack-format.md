# ADR-0002: レギュレーションパックの形式と継承

- 状態: 採用
- 日付: 2026-11-21

## 背景

レギュレーションは数か月ごとに変わる。新レギュレーション追加はデータの追加だけで済ませたい。過去パックも再分析のために残す。

## 決定

- 1パック = 1ディレクトリ、5ファイル（manifest / legal / overrides / rules / weights）。manifest 以外は省略可（省略 = 差分なし）。
- `manifest.extends` で親を1つだけ指定（単一継承）。多重継承は解決順の曖昧さを生むため採用しない。
- 継承の意味論:
  - 集合（使用可能ポケモン等）: `resolved = (parent ∪ add) − remove`。ルートパックで `remove` は不可（意味がないためエラー）。
  - `overrides`: エントリ（種族・技…）単位で深いマージ。子は変更したいフィールドだけ書く。値 `null` は「親の上書きを取り消す」。
  - `rules` / `weights`: 深いマージ。配列は置換。
  - `mechanics`: 子が書けば置換ではなく `{ add, remove }` 差分。
- 検証は2段階: (1) 各ファイルを zod で形式検証、(2) 解決後に参照整合性（Dex に存在しない種族/技/特性/持ち物、メガ可能なのに legal に含まれない種族、メガ種族に対応する進化前が legal でない、未知の Mechanic ID）を検証。エラーはすべて集めて `PackValidationError`（パス付き）で返す。
- 解決結果に `chain` と `contentHash`（キーをソートした正規化JSONの SHA-256 先頭16桁）を付与し、`AnalysisMeta` に記録する。
- ID は Showdown 互換 `toID`。パックの中で表示名で書かれていてもローダーが `toID` に正規化する。

## 代替案

- 毎回完全なリストを書く: 差分が見えずレビューしにくい。`reg:diff` で見られるが、継承の方が誤りが少ない。
- YAML: コメントが書けるのは利点だが、zod/JSON Schema と Web 埋め込みの単純さを優先。説明は `manifest.notes` に書く。
